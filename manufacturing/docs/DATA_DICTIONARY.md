# Data Dictionary

Project 03 - Manufacturing Performance Analytics.

All data in this project is 100 percent synthetic. It is generated by
`scripts/generate_data.py` from a fixed random seed (42), so every build
produces the same dataset. The imaginary plant is a speciality chemicals
packing plant with three packing lines and two product categories. No real
plant, company, product or measurement is represented, and all cost
assumptions are illustrative figures in Malaysian Ringgit (RM).

## Grain

One row per date x line x shift.

- 365 days: 2025-11-01 to 2026-10-31
- 3 lines: Line A, Line B, Line C
- 2 shifts: Day, Night
- Total: 2,190 rows

## Time model

Each shift is 8 hours and contains a 0.5 hour planned break. Planned
production time is therefore 7.5 hours per shift. The planned break is
excluded from every OEE denominator, so availability is measured against
7.5 hours, not 8.

For every row: `run_time_h + downtime_h = planned_time_h = 7.5`.

## Fields

| Field | Type | Unit | Description and constraints |
|---|---|---|---|
| date | text | ISO date | Production date, 2025-11-01 to 2026-10-31. |
| line | text | - | One of Line A, Line B, Line C. |
| shift | text | - | Day or Night. |
| category | text | - | Standard or Premium. Each line runs exactly one category per shift. Lines A and B mostly run Standard (about 85 percent of shifts), Line C mostly runs Premium. |
| planned_units | integer | units | Ideal rate x 7.5 h x planning factor. The factor is about 0.92, lifted to about 0.95 in the last three days of each month (the month end push). |
| actual_units | integer | units | Ideal rate x run_time_h x performance factor. The factor is 0.85 to 0.98, with Night shifts about two percentage points lower. Actual can exceed planned on a very good shift, because planned carries a planning margin. |
| good_units | integer | units | actual_units x quality factor (0.95 to 0.995, Premium slightly lower). Always less than or equal to actual_units. |
| rejected_units | integer | units | actual_units minus good_units. Never negative. |
| planned_time_h | real | hours | Always 7.5 (shift minus planned break). |
| run_time_h | real | hours | planned_time_h minus downtime_h. Never above 7.5, never negative. |
| downtime_h | real | hours | Unplanned downtime. Drawn from a lognormal distribution clipped to 0 to 2.5 hours, except in the Line B crash week (see story arcs) where it reaches 3.5 to 6.5 hours. |
| downtime_reason | text | - | Dominant cause for the row: Changeover, Equipment breakdown, Material shortage, Cleaning, Quality stop. Rows with under 0.1 hours of downtime get the reason None. |
| equipment_status | text | - | running, degraded or breakdown. Every Equipment breakdown row has status breakdown; a small share of other downtime rows are degraded. |
| energy_kwh | real | kWh | Base load 150 kWh per shift, plus 0.35 kWh per actual unit, plus idle draw of 90 kWh per downtime hour x 0.4 when the status is degraded or breakdown, plus small seeded noise. Never negative. |
| material_kg | real | kg | 0.8 kg per actual unit with 2 percent seeded noise. Never negative. |
| ideal_rate | integer | units/h | Convenience column: the nameplate rate for the row's line and category (see table below). Derived data, not exported in the JSON rows. |

## Ideal (nameplate) rates, units per hour

| Line | Standard | Premium |
|---|---|---|
| Line A | 1200 | 1000 |
| Line B | 1100 | 900 |
| Line C | 1150 | 950 |

## Relationships (database form)

In `data/manufacturing.db` the flat dataset is normalised:

- `lines` holds the three lines with their commissioning year (Line B,
  2008, is the oldest).
- `products` holds the two categories.
- `line_products` holds one ideal rate per line and product pair, because
  a nameplate rate belongs to the pair, not to a line or a product alone.
- `production_runs` holds one row per date x line x shift (enforced by a
  UNIQUE constraint) and references both `lines` and `products`.
- `downtime_events` holds the downtime cause and hours for each run that
  had any downtime, and references `production_runs`.

Foreign keys are switched on for every connection.

## Story arcs planted in the data

These are deliberate patterns so the dashboard has something to find.

1. **Line B is the oldest line.** Its breakdown downtime is about 1.5
   times that of the other lines all year round.
2. **Line B crash week, 9 to 15 March 2026.** Every Line B shift in that
   week is an Equipment breakdown with 3.5 to 6.5 hours of downtime, so
   Line B availability collapses and the plant's worst OEE days cluster
   there.
3. **Maintenance programme from 1 July 2026.** Breakdown downtime is cut
   by about 35 percent on all lines from that date onwards.
4. **Month end push.** The planning factor rises from about 0.92 to about
   0.95 in the last three days of each month, so planned units climb.
5. **Shift and category effects.** Night shifts run about two performance
   points below Day shifts, and Premium product runs at slightly lower
   quality than Standard.

## Cost assumptions

Held in the JSON `meta` block only and labelled illustrative. They are
never used to compute or claim savings.

- Energy: RM 0.08 per kWh
- Material: RM 1.20 per kg
- Value: RM 2.50 per good unit
